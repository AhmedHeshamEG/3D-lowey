# PROMPTS — 3D-lowey

## How to use this file

1. Create a GitHub repo. Put `context.md`, `phases.txt`, and this `prompt.md` in `/docs`.
2. Open your coding agent (e.g. Claude Code on the laptop) in the repo.
3. Paste **one** phase prompt below: "Phase 1", then later "Phase 2", then "Phase 3".
4. Every phase prompt tells the agent to read `/docs` and the **Shared Rules** first, so the rules apply to all three.
5. Install each build from the GitHub Actions artifact with Sideloadly.

---

## SHARED RULES (apply to every phase)

**You are the lead engineer of 3D-lowey**, a native iPad app for building low-poly-friendly 3D worlds, animating them, directing them with a camera, syncing them to narration, and exporting videos. The user, Hesham, is the director and product owner. He is not a low-level coder. You own the engineering; he owns the vision.

### Read first, every session
- `/docs/context.md` — the full vision, references, constraints, and decisions. Treat its **Decisions** table as binding unless you find a hard technical blocker; if so, write the problem and your proposed alternative in `DECISIONS.md` and continue with the alternative.
- `/docs/phases.txt` — the feature list and "done when" criteria for each phase.
- `ARCHITECTURE.md`, `DECISIONS.md`, `CHANGELOG.md` (create them in Phase 1 if missing).

### Hard constraints
- **Device:** iPad Air M3 13", iPadOS 27, Apple Pencil Pro. **No TrueDepth camera.**
- **No Mac.** Hesham never opens Xcode. Everything builds in **GitHub Actions macOS runners**. The Xcode project is generated by **XcodeGen** from `project.yml` — never commit hand-edited `.xcodeproj` files.
- **No paid Apple Developer account.** Release builds are unsigned device builds, then **ad-hoc codesigned** (so Sideloadly doesn't fail with "no code signature found"), packaged as `Payload/Lowey.app` → `Lowey.ipa`. Hesham re-signs with a free Apple ID via Sideloadly (7-day expiry). Never add entitlements a free Apple ID can't sign.
- **Deployment target:** iPadOS 26.0 (SpeechAnalyzer requires 26). Build with the newest Xcode available on the runner that supports the iPadOS 27 SDK; pin it explicitly in the workflow.
- **3D engine:** RealityKit (+ SwiftUI). **Do not use SceneKit** (soft-deprecated). Drop to Metal only where RealityKit can't do the job, and record why in `DECISIONS.md`.
- **No Whisper.** Speech → Apple on-device SpeechAnalyzer/SpeechTranscriber.
- **Local-first.** No accounts, no servers, no telemetry, no subscriptions. Network use only for the LAN Bridge (Phase 3) and user-initiated imports.
- **iPad-first UI**, touch + Pencil. Portrait and landscape. Stage Manager friendly.

### Architecture (non-negotiable core)
```
LoweyCore   (Swift package, pure Swift, no Apple UI/3D frameworks)
  Model:      Project, Scene, Object (id, name, type, parent, children),
              typed animatable Properties, Look, Camera, Timeline,
              Track, Keyframe, Easing, AssetRef, Prefab
  Commands:   every mutation is a Command { apply, revert, encode }.
              Undo/redo stack. Command batches (one undo step).
  Timeline:   evaluation(scene, time) -> resolved property values
  Serialize:  JSON (Codable), schema version + migrations
  Scripting:  Scene Script = JSON list of commands (JSON Schema in /schemas)
LoweyRender (RealityKit bridge: Core scene -> entities, diff-based sync,
               instancing, materials, lights, cameras, offscreen render)
LoweyApp    (SwiftUI app: stage, tools, panels, gestures, modes)
```
- The UI, gestures, Perform mode, scripting, AI, and Bridge **all** go through Commands. No side doors.
- Core has **no** RealityKit/UIKit imports so it tests fast (`swift test`), including on Linux runners if useful.
- Project on disk (visible in Files app):
  ```
  MyVideo.lowey/
    project.json
    scenes/<id>.json
    assets/            (copies of library assets used, for portability)
    audio/
    renders/
  ```
- Global asset library (outside projects) with `library.json` manifest: id, name, tags, thumbnail, format, rigType, clips, source, license. Projects reference assets by id; export copies them in.

### UI shape (keep consistent across phases)
- Full-screen **Stage** (3D viewport, game-like).
- **Left floating tool rail** (Feather-style): tool, color, size, opacity, undo/redo.
- **Top-left:** Home, menu. **Top-right mode switcher:** Build · Animate · Camera · Look · Export.
- **Bottom timeline drawer** (Procreate Dreams-style), resizable; modes Compose · Perform · Keyframe.
- **On-screen joystick** for move/rotate/scale ("editing feels like gaming").
- **Asset library** slide-in panel: search-first, big thumbnails, tags, recents. **Never** a giant template wall.
- **Inspector** only for the selection, few meaningful controls. Avoid slider walls.
- Dark neutral chrome, large targets, haptics, Pencil hover previews.
- Gestures: 1-finger orbit, 2-finger pan/zoom, Pencil draw/select, 2-finger tap undo, 3-finger tap redo.

### Product rules
- North star: **shorten idea-to-screen time.** Prefer one smart action over many settings.
- **No house style.** Every look property lives in the project's Look.
- **Few decisions, big results** (Townscaper/Tiny Glade model). No parametric slider-assets. No template walls.
- **AI proposes, the user decides.** Anything AI does is undoable and hand-editable.
- **Build once, reuse forever** (library + prefabs).

### Engineering rules
- Swift 6, strict concurrency. SwiftLint + SwiftFormat in CI.
- **Verify every Apple API against current documentation before using it.** Don't invent APIs. If an API is missing on iPadOS, write a spike, record the result in `DECISIONS.md`, pick the fallback.
- Small, focused commits with clear messages. Keep `main` always green.
- Unit tests for all Core logic; snapshot/round-trip tests for serialization; UI smoke tests for critical flows.
- Every feature: code + tests + docs line in `CHANGELOG.md`.
- Performance budget: 60 fps preview on iPad Air M3 with a typical scene (≈ 300 low-poly objects, 3 rigged characters, 2 particle systems). Profile before optimizing.
- Never lose user work: atomic writes, autosave, crash-safe recovery.
- Licensing: only use dependencies with permissive licenses; record them in `THIRD_PARTY.md`. Known-good: GLTFKit2 (glTF → RealityKit).

### CI/CD (created in Phase 1, extended later)
- `ci.yml` on every push/PR: lint → Core tests → app build (iPad simulator) → UI smoke tests → schema/round-trip tests.
- `release.yml` on push to `main` and tags `v*`: `xcodegen generate` → `xcodebuild … -sdk iphoneos -configuration Release CODE_SIGNING_ALLOWED=NO` → ad-hoc `codesign` the .app → zip `Payload/` → `Lowey.ipa` → upload artifact; on tags also create a GitHub Release with the .ipa and changelog.
- Build number = run number. Version = tag.
- Cache SwiftPM and DerivedData. macOS minutes cost more on private repos — keep jobs lean and skip the device build on docs-only changes.
- Document in `README.md`: how to download the .ipa and install with Sideloadly, and the 7-day re-sign.

### Working style with Hesham
- He is the director. When a choice changes the product (not just the code), ask him in one short question with a recommended default, then continue with the default if he doesn't answer.
- Report progress as: what's done, what's installable, what to test on the iPad (a short checklist), what's next.
- When a phase is complete, run through its "done when" list from `phases.txt`, tick each item with evidence (test name, screenshot path, or manual step), and tag the release.

## PHASE 1 PROMPT — Foundation & Build

```
Read /docs/context.md, /docs/phases.txt, and the SHARED RULES section of
/docs/prompt.md completely before doing anything. They are binding.

You are building PHASE 1 — FOUNDATION & BUILD of 3D-lowey (v0.1 → v0.4).
Goal: "I can build any world, save it, reopen it, and it looks great."

Deliver, in this order, keeping main green and installable at every step:

1. REPO & CI/CD
   - XcodeGen project.yml; packages LoweyCore, LoweyRender; app target
     LoweyApp. Bundle id com.hesham.lowey (display name "3D-lowey" —
     keep it in one place so it's a one-line rename).
   - ci.yml and release.yml exactly as in SHARED RULES. The very first
     milestone is: an empty app with a RealityKit viewport showing a
     rotating low-poly shape, built by CI into Lowey.ipa that installs
     via Sideloadly. Write the install steps in README.md.
   - ARCHITECTURE.md, DECISIONS.md, CHANGELOG.md, THIRD_PARTY.md.

2. CORE MODEL (LoweyCore)
   - Project, Scene, Object hierarchy, typed animatable Properties,
     Look, Camera stub, empty Timeline.
   - Command system with apply/revert/encode, batching, undo/redo.
   - JSON serialization with schemaVersion + migration hook.
   - Project folder format (see SHARED RULES), autosave, atomic writes.
   - Tests: every command reverts perfectly; save → load → identical
     scene; migration test with a fake v0 file.

3. RENDER BRIDGE (LoweyRender)
   - Core scene → RealityKit entities with diff-based sync (only changed
     objects update). Instancing for repeated assets.
   - Materials: palette-bound colors, smooth/flat shading toggle,
     emissive. Lights with shadows. Sky/gradient, stars, fog, ground.
   - Offscreen snapshot capability (needed for thumbnails now and video
     export in Phase 2). Spike the best iPadOS path for rendering a
     RealityKit scene to a texture at an arbitrary time (e.g.
     RealityRenderer if available on iPadOS, otherwise the best
     supported alternative, otherwise Metal). Record the result in
     DECISIONS.md. This must be solid; Phase 2 export depends on it.

4. VIEWPORT & NAVIGATION
   - Orbit/pan/zoom gestures, frame selection, quick views (top, front,
     side, perspective), orthographic toggle, grid, gizmos, selection
     (tap, Pencil, lasso, multi-select).

5. ASSETS & GLOBAL LIBRARY
   - Import USDZ, glTF/GLB (GLTFKit2 → RealityKit), OBJ from Files,
     drag & drop, share sheet.
   - Global library with library.json manifest, auto thumbnails,
     search-first panel, tags, favorites, recents.
   - Prefabs: save selection/group/drawn object to library; instances
     update when the prefab changes.
   - Projects reference by id; "Export project" copies assets in.
   - Keep rigged assets' skeleton + clips intact on import (they're used
     in Phase 2); show a "rigged" badge.

6. BUILDING & COMPOSITION
   - Primitives for blockout (neutral material). "Swap" blockout → asset
     keeping transform.
   - Joystick transform control + gizmos + numeric inspector.
   - Snapping (grid, surface, objects, rotation steps).
   - Duplicate, array (line/grid/circle), scatter over an area with
     random rotation/scale ranges — one gesture, sensible defaults.
   - Groups, outliner, lock/hide, align/distribute.

7. DRAWING IN 3D (Feather-inspired, easier)
   - Guide surfaces: plane (lock to ortho view), box, cylinder, sphere,
     and "draw on an existing object".
   - Pencil pressure strokes → smoothed tube/ribbon meshes.
   - Extrude a drawn outline; revolve a drawn profile.
   - Mirror/symmetry. Save result to library.

8. LOOK (per project)
   - Look panel: shading, palette (with eyedropper and palette-bound
     objects), lighting presets (day, golden hour, dusk, night, space,
     studio) + custom lights, sky, stars, fog, ground.
   - Save a look as an environment preset in the library.

9. UI SHELL
   - Home (project grid with thumbnails), Stage, left tool rail,
     top-right mode switcher (Build active; Animate/Camera/Look/Export
     present, Look functional, others placeholders), inspector,
     library panel.
   - Snapshot export: PNG in 16:9, 9:16, 1:1.

DONE WHEN (verify each, with evidence, then tag v0.4.0):
   - CI green; every main push produces an installable Lowey.ipa.
   - I can build the Enigma sets as static scenes — a desk with a paper
     and a warm lamp in a dark room; a room of people at PCs; a hero
     robot in a cave — save, close, reopen: identical.
   - Undo/redo works for every action.
   - A glTF animal pack imports with thumbnails; 50 instances placed
     with no frame drop on iPad Air M3.
   - LoweyCore coverage ≥ 80%.

Start by writing a short plan (milestones + what I'll be able to test
after each), then execute milestone by milestone. After each milestone:
push, confirm CI green, and give me a 3–5 item iPad test checklist.
```

## PHASE 2 PROMPT — Motion, Camera, Characters, Export

```
Read /docs/context.md, /docs/phases.txt, the SHARED RULES section of
/docs/prompt.md, ARCHITECTURE.md and DECISIONS.md completely before doing
anything. Phase 1 is complete; build on it, don't rewrite it. All new
behavior goes through the existing Command system.

You are building PHASE 2 — MOTION, CAMERA, CHARACTERS, EXPORT (v0.5 → v0.8).
Goal: "I can make it move like I imagine and export a real video."

Deliver, in this order:

1. TIMELINE
   - Bottom drawer timeline: tracks per object/property, zoom, scrub,
     loop region, markers, project frame rate (24/25/30/60).
   - Modes: Compose (arrange), Perform (record), Keyframe (edit).
   - Timeline evaluation lives in LoweyCore and is fully tested
     (value at any time, easing math, stepping).

2. KEYFRAMES & EASING
   - Keyframe any animatable property.
   - Easing presets (linear, in/out, back/overshoot, bounce, elastic,
     step) + graph editor with draggable curve handles.
   - Copy/paste/mirror/retime/reverse keys.
   - "On twos / on threes" stepping per object and per project, so
     characters can step while the camera stays smooth.

3. PERFORM MODE (motion capture by touch — Procreate Dreams "Performing")
   - Record → "Ready" → playback runs → drag/scale/rotate content with
     finger or Pencil → keyframes recorded in real time at project fps.
   - Pencil Pro barrel roll = rotation while moving (toggleable).
   - Lift finger = pause recording; touch again = resume.
   - Motion filtering % (smoothing) setting; 0% captures everything.
   - Any animatable property can be performed (e.g. light intensity,
     camera focal length) via on-screen sliders.
   - Performing over an existing range replaces it (one undo step).

4. ANIMATION PRESETS
   - Pop in/out, grow, shrink, bounce, wiggle, float, spin, shake, pulse,
     fade, slide in, drop in, typewriter. Each creates real, editable
     keyframes. One tap from the inspector.

5. MASS ANIMATION & PROGRAMMATIC LAYER
   - Multi-select → preset with stagger (delay per object), ordering
     (selection, axis, distance from a point = wave), randomize
     (timing, amplitude).
   - Behaviors: follow path, look at, orbit, noise/wobble, wind sway,
     bob on water. Behaviors are evaluable at any time
     (deterministic) and can be baked to keys.
   - Animated generators (growing array, animated scatter).
   - Scripting: JavaScriptCore runtime exposing the Command API
     (create objects, set properties, add keyframes, query scene),
     sandboxed, with a script panel, errors shown inline, and scripts
     saved as library assets. Include 3 example scripts: forest grows
     in, flock of birds, crowd walks in.
   - Simulations: RealityKit physics (fall/collide/explode) and scripted
     sims, BAKED to keyframes so they're editable and export
     deterministically.

6. CHARACTERS & RIGGING
   - Play imported animation clips on skinned characters.
   - Skeleton standards: Humanoid, Quadruped, Bird, Custom. Auto-map
     common bone naming conventions (Mixamo, Quaternius-style, generic)
     to the standard; manual mapping UI for the rest.
   - Retargeting: any clip for a standard plays on any character of
     that standard. Verify with a humanoid clip on 2 different humans
     and a walk clip on 2 different quadrupeds.
   - Clip track: play, loop, speed, blend/crossfade between clips.
   - Walk along a path with root motion or path-follow + foot planting.
   - Puppet rigs: build a character from rigid parts with pivots
     in-app (no skinning), animate with keys/Perform.
   - Simple IK: feet to ground, look-at for head, hand reach.
   - Crowd tool: N instances of a character with offset/varied clips.

7. CAMERA SYSTEM
   - Camera objects, multiple per scene, camera-cut track.
   - Move presets: push-in, pull-out, punch-in, orbit, dolly, truck,
     crane, whip pan, shake, follow target, reveal — each generates
     editable keys.
   - Lens: focal length/FOV, depth of field (focus distance, aperture),
     animated focus pulls.
   - Virtual camera: ARKit world tracking (rear camera, works on iPad
     Air) drives the scene camera as I move the iPad; record it via
     Perform mode; scale factor for "small room → big world".
   - Framing guides: 16:9, 9:16, 1:1 + safe zones; per-shot 16:9 and
     9:16 framings so one scene exports both.

8. RENDERING & EXPORT
   - Export renders frame-by-frame at a fixed timestep using the
     offscreen path from Phase 1 → AVAssetWriter → .mp4 (H.264/HEVC).
   - Full video, range, 16:9 + 9:16 in one job, PNG sequence, single
     frame, transparent background option.
   - 3D export: USDZ/glTF of selection or scene.
   - Background export with progress and cancel; output saved to
     project renders/ and shareable to Photos/Files.
   - Deterministic: the same scene exports identically twice (test it).

DONE WHEN (verify each, with evidence, then tag v0.8.0):
   - The Enigma opening is fully animated: paper under a warm lamp and
     the camera pushes in; the room of people at PCs (crowd, typing
     clips); the paper grows huge over the room; a big X pops; a hero
     robot appears; a question mark pops.
   - At least one motion recorded with Perform, one with keyframes, one
     with a mass stagger, one camera move recorded with the iPad as the
     camera.
   - A rigged tiger walks along a path with a real walk clip.
   - The same sequence exports as 16:9 and 9:16 videos that play in
     Photos.
   - Timeline/easing/behavior logic is unit tested in LoweyCore.

Start with a short milestone plan, then execute. After each milestone:
push, CI green, iPad test checklist.
```

## PHASE 3 PROMPT — Story, Voice, VFX, AI, Polish → v1.0

```
Read /docs/context.md, /docs/phases.txt, the SHARED RULES section of
/docs/prompt.md, ARCHITECTURE.md and DECISIONS.md completely before doing
anything. Phases 1–2 are complete; build on them. All new behavior goes
through the Command system.

You are building PHASE 3 — STORY, VOICE, VFX, AI, POLISH (v0.9 → v1.0).
Goal: "I read my script and the video comes to life fast. Final product."
This ends in v1.0.0 — a complete, polished, reliable app. Not an MVP.

Deliver, in this order:

1. AUDIO & NARRATION
   - Audio tracks: voiceover, SFX, music; waveforms; volume and fade
     envelopes; in-app voiceover recording; import audio files.
   - Word timing with Apple on-device SpeechAnalyzer + SpeechTranscriber
     using the audioTimeRange attribute. NO Whisper. Handle: model
     asset download on first use, audio format conversion to the
     analyzer's best format, English + Arabic + Italian if supported.
   - Words become timeline markers; snapping to words; transcript panel
     (tap word → jump; select phrase → attach animation/camera move).
   - Editable transcript corrections that keep timings.

2. LIP SYNC & FACE
   - Visemes from word timings (word → phonemes via an embedded
     permissively licensed pronunciation dictionary + fallback
     letter-to-sound rules) → mouth shapes over time; amplitude-driven
     jaw fallback for unknown words.
   - Two mouth systems: blendshapes on 3D faces; swappable mouth
     meshes/textures (Toonsquid-style) for stylized characters.
   - Face performance via Vision face landmarks from the iPad front
     camera (no TrueDepth on this iPad): brows, blink, mouth open/wide,
     head rotation → character; recorded through Perform mode.
   - Optional iPhone companion mode: if an iPhone with Face ID runs the
     app, it streams ARKit face tracking over LAN to the iPad.

3. HESHAM'S OWN CHARACTER
   - Character builder: pick parts (head, hair, face, body, clothes)
     from the library + palette colors. Few decisions.
   - Built on the Humanoid standard (inherits all clips), face and
     lip sync ready, saved to the library.

4. TEXT & OVERLAYS
   - 2D overlays: titles, labels, arrows, highlights, big X, question
     mark, shapes, images — all animatable, with presets.
   - 3D extruded text in the world.
   - Captions from the transcript, styleable, burn-in on export
     (toggle), SRT export.

5. VFX & POST
   - Particles with presets: fire, sparks, smoke, dust, magic, rain,
     snow, confetti, embers, explosion; few controls each.
   - Post: bloom/glow, vignette, grain, color grade, outline,
     chromatic aberration, pixelate/retro, lens blur, collage/paper
     texture overlays. Applied in preview and in export identically.
   - Screen effects: flash, shake, speed lines, zoom blur, glitch.
   - Transitions: cut, fade, wipe, zoom-through, match-cut helper.

6. AI LAYER
   - Scene Script: finalize the JSON Schema (/schemas/scene-script.json)
     and docs with examples. Import from Files/share sheet/clipboard →
     preview diff → apply as one undo step.
   - LAN Bridge in the app: HTTP + WebSocket, off by default, pairing
     code, LAN-only, exposes command API, scene/asset queries,
     snapshot render.
   - /tools/lowey-mcp: an MCP server (Python or Node, pick the one
     with the best current MCP SDK and document it) that runs on the
     laptop and proxies to the Bridge.
       Tools: get_scene, list_assets, place_asset, create_object,
       set_property, add_keyframes, apply_preset, camera_move,
       set_look, add_overlay, attach_to_word, snapshot.
       Resources: scene, look, asset index, transcript.
       Prompts: breakdown_script, plan_shots, build_scene,
       direct_camera, sync_to_voiceover.
   - /skills: Claude skills (SKILL.md each) — script-breakdown,
     shot-planner, scene-builder, camera-director — that use the
     project's Look as defaults and keep token use low.
   - Model-agnostic: document usage with Claude and with any other
     MCP-capable client; Scene Scripts work with any model.
   - AI actions are always previewable, undoable, hand-editable.

7. LAPTOP LINK
   - Pairing over LAN; send files laptop → iPad library; send renders
     iPad → laptop; a tiny laptop companion script/CLI in /tools.
   - Generator hook: the companion can run laptop-side generators
     (Blender Python scripts, a local text-to-3D model when Hesham adds
     one) and push the resulting asset straight into the iPad library.

8. PROJECTS & POLISH
   - Project management: duplicate, rename, archive, .lowey package
     export/import, copy scenes between projects.
   - Performance pass: LOD, instancing audit, texture compression,
     thermal-aware preview quality; meet the 60 fps budget.
   - Onboarding: sample project (low-poly island fly-through) + short
     interactive tour.
   - Magic Keyboard shortcuts, Pencil hover previews, haptics,
     accessibility labels, localized strings scaffold.
   - Local crash/diagnostic log + "export diagnostics".
   - Final UI polish pass for consistency with the UI shape in SHARED
     RULES.

DONE WHEN (verify each with evidence, then tag v1.0.0):
   - I import the Enigma voiceover; the transcript appears with word
     markers; every shot is synced to its words.
   - My own character narrates at least one shot with automatic lip
     sync and face performance.
   - Claude, via lowey-mcp on the laptop, builds one full shot from a
     line of the script, and I then edit it by hand.
   - VFX, overlays, captions and post are in the video.
   - The full Enigma video exports in 16:9 and 9:16, upload-ready.
   - Idea-to-screen time for a new simple shot (world + character +
     camera move + synced to a word) is measured and written in
     README.md.
   - No known crash, CI green, README/ARCHITECTURE/DECISIONS/CHANGELOG
     up to date, release v1.0.0 published with the .ipa.

Start with a short milestone plan, then execute. After each milestone:
push, CI green, iPad test checklist.
```
